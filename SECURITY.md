# Security Policy

## Supported Versions

Only the latest major and minor release versions receive security patches and updates.

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

We take the security of legal and investigative document management seriously. If you discover a security vulnerability, please report it responsibly.

### How to Report
- **Email:** Send details of the vulnerability to `harshit2k9@gmail.com` (or your primary contact email).
- **Do NOT** open a public GitHub issue for security vulnerabilities.

### What to Include
Please include as much detail as possible to help us reproduce and address the issue:
1. Type of vulnerability (e.g., Auth Bypass, Privilege Escalation, Unauthorized Data Access).
2. Step-by-step instructions to reproduce the issue.
3. Proof-of-concept (PoC) code or screenshots, if applicable.
4. Affected endpoints, user roles, or components.

### Response Timeline
- **Acknowledgement:** We will acknowledge receipt of your report within **24–48 hours**.
- **Status Updates:** You will receive regular progress updates at least once every **3 business days**.
- **Resolution:** If confirmed, a patch will be prepared and deployed as soon as possible, depending on severity.

### Disclosure Policy
We ask that you keep any reported vulnerabilities confidential until a fix has been officially deployed and announced.
